# 番茄投稿助手

帮用户把书发上番茄小说。通过浏览器自动化操作用户**已登录的日常 Chrome**，不逆向任何接口。书籍信息可来自本地文件或墨语 MCP 线上书籍。

## 任务线纪律（先分清哪条线再动手）

三条任务线**互相独立**：

- **建书**：本地准备好创建新书的内容（收集字段 + 简介改写 + 标签选型）→ 打开网页直接填表 + 传封面 → 用户确认后点「立即创建」。就这三步，**不拆章、不扫正文、不做任何额外检查**。
- **发章节**：拆章 → 逐章存草稿。**没有自动扫描**。
- **扫描修库**：独立任务，**仅当用户明确要求**（说"扫描 / 查AI痕迹 / 修库"）时才执行，绝不与建书或发章节捆绑，也不预告、不排进 todo。

**省时纪律（硬性）**：用户没明确要求检查，就不检查——不 grep 正文核词、不翻旧会话存档和 /tmp 进度文件、不做多余的页面状态核验（打开建书页前最多确认一次登录态和目标书是否已存在）、不主动规划扫描步骤。材料定稿后直接进填表。

拿不准用户要哪条线，问一句再动。

## 建书（三步）

### 第一步 · 本地定稿材料

**来源A·本地信息文件**（md/txt）：

```markdown
书名：（≤15字，仅中英文/数字/符号 ，：！？【】，签约前可改）
目标读者：男频 / 女频
阅读标签：（主分类1个 + 主题/角色/情节各≤2，从固定值库选）
内容标签：（情节/人设各≤4、情感≤2、世界观≤1，从固定值库选）
主角名：（2个，各≤5字）
简介：（50–500字，读者向书城文案）
封面：（图片路径，可选）
```

**来源B·墨语 MCP 线上书籍**（用户给出 project_id 或书名，先 `list_projects` 对号），三个调用拿全：

1. `get_project(project_id)` → 书名、简介、题材（题材用于选标参考）。注意：这里的简介是**内部剧情梗概**（含结局、反转、设计语），不能直接照贴，按下述改写
2. `list_characters(project_id)` → 女主/男主姓名填主角名（各≤5字；超了问用户用简称还是昵称）
3. `get_export_links(project_id)` → `cover_url` 下载用于上传；`txt_url` 只记录不下载，留给发章节任务（24h 有效，过期重取）

**简介改写（硬性要求）**：番茄简介是**面向读者的书城文案**——前两句抛人设+反差钩子，中段给卖点（机制/金手指/CP张力），结尾留一句悬念钩子；**不剧透结局和反转，不出现"对家CP""机制""结尾她…"这类内部设计语言**。梗概里的元素只取前 1/3 作钩子素材。用户自己提供的读者向文案照用不改。

**标签**：查固定值库 `references/fanqie-tags.md` 按小说内容选，**不要重新爬全量面板**。规则：阅读标签=主分类必选1个、主题/角色/情节各≤2、签约后不能改；内容标签=情节/人设各≤4、情感≤2、世界观≤1（均可留空）。选标策略在该文件里：主分类按题材对号，拿不准的组宁缺勿滥（架空世界观留空），标签必须在简介/大纲里有实锤。

**校验后直接进第二步**：书名 ≤15 字且字合法（半角标点转全角）；简介 50–500 字。不擅自删改用户定稿文案。**简介改写稿不单独确认一轮**——直接填表，随整表回显在第三步一次性确认。

### 第二步 · 开网页填表 + 传封面

用环境里可用的浏览器控制能力（官方 browser-use control-browser 或用户 browser-cdp 技能）：

- **安全红线**（用户的 Chrome 是主力浏览器）：绝不 pkill/重启浏览器进程，绝不发全局按键，只走调试协议操作标签页。用户装有蛙蛙投稿助手扩展会抢前台标签页——操作前先确认当前 tab 是番茄页面。
- 打开 `https://fanqienovel.com/main/writer/create?enter_from=book_manage`。未登录停下让用户手动登录，**绝不代填账号密码**。
- 按 `references/fanqie-create-flow.md` 操作（真实表单规格、封面上传流程、标签点选 playbook 都在里面）。**文档只是观察记录，一切以现场页面实际元素为准**。
- 书名只允许中英文、数字及符号 ，：！？【】，半角标点先转全角。
- 改输入框内容用 JS native setter + input 事件（自动化 type 命令不清空原值，会叠字）。

### 第三步 · 用户确认后创建

表单填完、封面传完，**整表截图回显一次**，用户点头才点「立即创建」。用户要先改字段就改完再回显。创建后汇报书名和后台状态。

## 发章节（独立任务）

**首选路径：交接给用户已安装的「番茄发文助手」Chrome 扩展**——它已实现整本 TXT 自动切分、断点续传、弹窗斩杀、AI声明=否、定时/直发/仅草稿三模式、悬浮进度面板。**不要用 CDP 手工逐章粘贴重复造轮子**；手工路径仅作扩展不可用时的兜底。

### 1. 交接准备（agent 只备料，不抢活）

1. 拿整本 TXT：墨语书用 `get_export_links` 的 `txt_url` 下载（24h 有效），本地稿直接用文件。告知用户**文件绝对路径**。
2. 格式核对：扩展按「第12章 标题」（**阿拉伯数字**章号）行自动切分。中文数字章节头（第十二章）切不了——先用本技能 `split_chapters.py` 拆成单章 txt 文件夹，让用户走扩展的【已拆分文件夹】导入。
3. 发布模式默认**定时发布**：开始日期=**当天**、发布时间 08:00（扩展默认）、**每 2 章 +1 天（即每天 2 章）**，分卷号留 0；用户明确说存草稿/直发才改。其余提醒：扩展弹窗里的**书名必须与后台书卡逐字一致**（含标点，否则找不到卡片）；运行期间不要操作工作标签页。
4. 前提：扩展已安装、浏览器已登录作家后台。未安装就让用户先装（商店地址待补），别急着手工兜底。扩展的详细用法看它自己的文档和弹窗界面，本技能不重复教程。

### 2. AI 驱动扩展（可选路径，用户要求时代填）

弹窗页可以当标签页驱动（2026-09-29 实测可行）：`chrome-extension://<扩展ID>/popup/popup.html`（扩展 ID 从 chrome://extensions 页读，本机当前=nhaopminmijpcibmknfimpichpbibicp）。流程：填书名 → 用上传命令把 TXT 塞进「选择整本小说 TXT」的文件输入 → 等切分清单出来核对章数 → 选**定时发布**单选并按上面默认填当天/08:00/每2章 → **【开始发布】默认留用户亲手点，用户明确授权才代点且只点一次**。运行期从弹窗标签页读章节清单与状态做汇报，绝不碰番茄工作标签页。排程完成后提醒用户可在后台定时列表核对。

### 3. 运行期纪律（硬性）

扩展运行期间 agent **绝不碰番茄标签页**：不导航、不点击、不往该 tab 注入 eval、不截图干扰；也不要新开别的番茄后台标签页（扩展靠标签页识别，串台会出错）。等用户报完成、或进度浮层显示结束后再动。完成后按扩展的「已发记录」口径汇报，定时模式提醒用户可在后台定时列表核对排程。

### 兜底：扩展不可用时才手工逐章

```bash
python3 "<本技能目录>/scripts/split_chapters.py" <稿件路径> -o /tmp/fanqie_chapters.json
```

章节列表完整展示给用户过目，warnings 逐个确认；**正文一个字不改**。然后逐章新建：填标题 → 粘贴正文 → **存草稿**（用户明确说发布才发布，且每章发布前回显确认）。粘贴完抽查首尾防截断；页面卡顿改分段粘贴；单次最多 10 章左右。

## 扫描修库（独立任务，仅用户明确要求时执行）

- 书在墨语 MCP：用平台 `scan_chapter_traces` 扫 AI 痕迹、英文混入、内容泄漏（思考链标签/元信息/假章头/残 tag），结果按章回显，有问题的章先修再发；泄漏类只人工清理，不走自动改写。
- 本地稿件：正则粗查英文混入与泄漏标记（如 `respond with`、`<thinking>`、`{{`、行首元信息），命中的段落回显给用户定夺。
- 用户没有要求扫描时，**不要**把扫描排进发章节的计划或 todo。

## 红线（全程）

- 出现验证码、安全弹窗、频繁报错 → **立刻停**，交给用户手动处理，好了再说"继续"。
- 只操作作品创建和章节相关页面：**不碰账号设置、不点签约、不动任何涉及钱和合同的入口**。
- 默认发布形态：扩展发章节=**定时发布（当天起、每天2章）**；手工兜底与建书表单=存草稿。「立即创建」「开始发布」类外发动作必须用户确认（开始发布默认用户亲手点）。
- 不改写用户正文内容。

## 收尾汇报

按任务线如实汇报：建书=作品是否创建成功（书名/链接）、封面是否传了、标签选了哪些；发章节=定时排程章数/存草稿章数、失败/跳过章节及原因、剩余未排章数；扫描=命中章节清单。提醒：定时模式可在后台定时列表核对排程；txt_url 过期要重取。
