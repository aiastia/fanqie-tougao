# 番茄投稿助手

帮用户把书发上番茄小说。全程浏览器自动化操作用户**已登录的日常 Chrome**，不逆向任何接口。书籍信息可来自本地文件或墨语 MCP 线上书籍。

## 两阶段纪律（先分清阶段再动手）

- **阶段一·建书**：只需要固定几样——书名、签约模式、目标读者、阅读标签、内容标签、主角名、简介、封面。**不拆章、不扫正文、不碰稿件**。用户说"建书/创建新书"就只做这一阶段。
- **阶段二·发章节**：才轮到稿件——AI痕迹/泄漏扫描（投稿前修库纪律）、拆章、逐章存草稿。用户说"发章节/发正文/投稿正文"才进入。
- 拿不准用户要哪段就直接问一句，别自作主张把两段连跑。

## 阶段一·建书

### 1. 收集固定清单（缺什么问什么，不替用户编造）

**来源A·本地信息文件**（md/txt）：

```markdown
书名：（≤15字，仅中英文/数字/符号 ，：！？【】，签约前可改）
目标读者：男频 / 女频
阅读标签：（主分类1个 + 主题/角色/情节各≤2，从固定值库选）
内容标签：（情节/人设各≤4、情感≤2、世界观≤1，从固定值库选）
主角名：（2个，各≤5字）
简介：（50–500字，突出卖点）
封面：（图片路径，可选）
```

**来源B·墨语 MCP 线上书籍**（用户给出 project_id 或书名，先 `list_projects` 对号）：

1. `get_project(project_id)` → 书名、简介、题材（题材用于选标参考，最终以固定值库为准）。注意：这里的简介是**内部剧情梗概**（含结局、反转、设计语），不能直接照贴，按下方"简介改写"处理
2. `list_characters(project_id)` → 取女主/男主姓名填主角名（各≤5字；超了问用户用简称还是昵称）
3. `get_export_links(project_id)` → `cover_url` 用 curl 下载后上传封面；`txt_url` **只记录不下载**，留给阶段二（24h 有效，过期重取）

**简介改写（硬性要求）**：番茄简介必须是**面向读者**的书城文案，不是剧情梗概——前两句抛人设+反差钩子，中段给卖点（机制/金手指/CP张力），结尾留一句悬念钩子；**不剧透结局和反转，不出现"对家CP""机制""结尾她…"这类内部设计语言**。梗概里的元素只取前 1/3 用作钩子素材。改写稿必须回显给用户确认后才填表；用户自己提供的简介若已是读者向文案则照用不改。

**校验**：书名 ≤15 字且字合法（半角标点先转全角）；简介 50–500 字；不擅自删改用户定稿的文案。

### 2. 标签

直接查固定值库 `references/fanqie-tags.md` 按小说内容选，**不要重新爬全量面板**。规则：阅读标签=主分类必选1个、主题/角色/情节各≤2、签约后不能改；内容标签=情节/人设各≤4、情感≤2、世界观≤1（均可留空）。选标策略在该文件里：主分类按题材对号，拿不准的组宁缺勿滥（架空世界观留空），标签必须在简介/大纲里有实锤。

**点选交互必须照 `references/fanqie-create-flow.md` 的「标签面板交互 playbook」执行**：弃用 @eXX ref、事件派发到最内层 title 元素、一次一个间隔 1.2s、逐个验证、未确认关闭=全作废。这是双会话实测踩坑换来的，别省步骤。

### 3. 填表与创建

用环境里可用的浏览器控制能力（官方 browser-use control-browser 或用户 browser-cdp 技能）：

- **安全红线**（用户的 Chrome 是主力浏览器）：绝不 pkill/重启浏览器进程，绝不发全局按键，只走调试协议操作标签页。注意用户装有蛙蛙投稿助手扩展，会抢前台标签页——每次操作前先确认当前 tab 是番茄页面。
- 打开 `https://fanqienovel.com/main/writer/create?enter_from=book_manage`。未登录就停下让用户手动登录，**绝不代填账号密码**。
- 按参考文档 `references/fanqie-create-flow.md` 操作（真实表单规格、封面上传流程都在里面）。**文档只是观察记录，一切以现场页面实际元素为准**，找不到控件就重新观察。
- 书名字符限制：平台只允许中英文、数字及符号 ，：！？【】，半角标点先转全角。
- 改输入框内容用 JS native setter + input 事件（自动化 type 命令不清空原值，会叠字）。
- 表单逐项填完**截图或逐字段回显给用户确认**，用户点头才点「立即创建」。

## 阶段二·发章节

### 1. 扫描（投稿前修库纪律，先扫后拆）

- 书在墨语 MCP：用平台 `scan_chapter_traces` 扫 AI 痕迹、英文混入、内容泄漏（思考链标签/元信息/假章头/残 tag），有问题的章先修再发；泄漏类只人工清理，不走自动改写。
- 本地稿件：至少正则粗查英文混入与泄漏标记（如 `respond with`、`<thinking>`、`{{`、行首元信息），命中的段落回显给用户定夺。
- **正文一个字都不许改**，只允许拆分、去 BOM/空白。

### 2. 拆章

```bash
python3 "<本技能目录>/scripts/split_chapters.py" <稿件路径> -o /tmp/fanqie_chapters.json
```

章节列表（编号/标题/字数）完整展示给用户过目；warnings 的过短/过长章逐个确认是正文还是标记噪音；拆错了改稿件或用 `--heading-pattern` 重拆。

### 3. 逐章存草稿

进入作品 → 章节管理 → 逐章新建：填标题 → 粘贴正文 → **存草稿**（用户明确说发布才发布，且每章发布前回显确认）。粘贴完抽查首尾防截断；页面卡顿改分段粘贴。逐章放慢节奏，单次最多 10 章左右。

## 红线（全程）

- 出现验证码、安全弹窗、频繁报错 → **立刻停**，交给用户手动处理，好了再说"继续"。
- 只操作作品创建和章节相关页面：**不碰账号设置、不点签约、不动任何涉及钱和合同的入口**。
- 默认一切存草稿；「立即创建」「发布」类外发动作必须用户逐次确认。
- 不改写用户正文内容。

## 收尾汇报

按阶段如实汇报：阶段一=作品是否创建成功（书名/链接）、封面是否传了、标签选了哪些；阶段二=存草稿章数、发布章数（若有）、失败/跳过章节及原因、剩余未发章数。提醒：草稿要用户人工点发布；封面没传记得补；txt_url 过期要重取。
